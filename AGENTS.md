# AGENTS.md

## Project overview

Electron GUI (CommonJS, no runtime deps) for wireproxy-awg — a userspace AmneziaWG client (`bin/wireproxy.exe`) that exposes SOCKS5/HTTP proxies over a tunnel. The app spawns the exe, validates configs, and monitors it via a local health HTTP endpoint.

## Repo layout

- `index.js` — thin Electron main-process bootstrap: window/tray/autostart wiring, `VpnEngine` construction, event bridge (engine events → `webContents.send` + `trayCtrl.sync()`), `app.setLoginItemSettings`, single-instance lock. No logic beyond that.
- `core/` — pure-Node modules (no Electron imports): `vpn-engine.js` (VpnEngine: spawns `hops[]`, state machine, 1s health polling, chain orchestration, config-test; emits `status/log/readyz/metrics`), `config-parser.js`, `metrics.js`, `derived-config.js`, `process-utils.js`, `wireproxy-path.js`, `profiles.js` (profile metadata/config persistence), `chains.js` (chain definitions, `userData/chains.json`, atomic tmp+rename), `settings.js` (`userData/settings.json` persistence; legacy `defaultProfileId` fallback), `relay.js` (`UdpOverSocksRelay` UDP-over-SOCKS5 forwarder + RFC 1928 encode/parse helpers).
- `services/` — dependency-injected services: `targets.js` (default target resolution), `autostart.js`, `settings-actions.js` (single source of truth for tray+UI settings setters).
- `ipc/handlers.js` — registers all 21 `ipcMain.handle` channels, delegating to injected core/services.
- `preload.js` — contextBridge exposing `window.wireproxyApi`. Only channels whitelisted here are reachable from the renderer.
- `tray.js` — `TrayController` (Electron Tray): dynamic context menu (show/hide, start/stop, autostart/autoconnect checkboxes, quit). Synced from main via `sync()`.
- `icon.png` — app icon: used for the window, the tray, and as `win.icon` for electron-builder (500×500 PNG).
- `renderer/` — plain HTML/CSS/JS, no framework; CSP is `default-src 'self'; style-src 'self'`. Three scripts, loaded in order: `state.js` (shared `window.WGApp` state + helpers), `ui.js` (DOM refs + rendering/helpers), `renderer.js` (actions, event wiring, bootstrap).
- `bin/wireproxy.exe` — prebuilt binary. Required at runtime but gitignored and not committed. Generated by `npm run fetch:wireproxy` (downloads the pinned release); never rebuild or delete it by hand.
- `scripts/fetch-wireproxy.js` — downloads/extracts wireproxy from GitHub releases (version pinned in `package.json`).
- `electron-builder.yml` — packaging config: portable win target, `bin/wireproxy.exe` shipped via `extraResources` → `resources/bin/`.
- `wireproxy-awg/` — vendored upstream Go source (its own git repo, gitignored). Read-only reference for config format/docs.
- `test/` — `node --test` unit tests for `core/` and `services/` modules.

## Commands

- `npm start` — runs the app (`electron .`).
- `npm test` — `node --test` unit tests for `core/` and `services/`.
- `npm run fetch:wireproxy` — downloads the pinned wireproxy release, verifies sha256, extracts `wireproxy.exe` into `bin/`.
- `npm run dist` — `fetch:wireproxy` + electron-builder → `dist/*-portable.exe`. Requires network; skips nothing.
- No lint/format/typecheck tooling configured.

## Packaging

- wireproxy release is pinned in `package.json` → `config.wireproxy` (repo/version/asset/sha256) — never reference `latest`; bump the pin and sha256 to upgrade.
- In the packaged app, `index.js` resolves `WIREPROXY_PATH` via `process.resourcesPath` (`app.isPackaged`); in dev it uses `bin/wireproxy.exe` beside `__dirname`.
- `electron-builder.yml` `files` is an explicit whitelist — any new root JS module, asset (like `icon.png`), or directory (`core/`, `services/`, `ipc/`, `renderer/`) MUST be added there or it silently won't ship. `bin/wireproxy.exe` goes only via `extraResources`, never via `files`.

## Profile storage

- Profiles live in `app.getPath('userData')/profiles/`: `index.json` (metadata, written atomically via tmp+rename) and one `<uuid>.conf` per profile holding the raw INI text.
- On first run, a legacy `userData/wireproxy.conf` is migrated into a profile.
- The last remaining profile cannot be deleted.
- Chains live in `userData/chains.json` (same atomic pattern). Deleting a profile prunes it from all chains (`chains.pruneDeletedProfiles`); deleting a profile that is part of the running connection stops the run first.

## IPC contract

- Renderer→main invoke: `profiles:list/get/create/save/validate/rename/delete`, `chains:list/get/create/save/rename/delete`, `vpn:start/stop/state`, `settings:get/setAutostart/setAutoconnect/setDefaultTarget`.
- `vpn:start` accepts `{ id, text, silent }` (single profile) or `{ chainId, silent }` (chain).
- Main→renderer push: `vpn:status` (carries `state`, `activeProfileId` = exit hop, `activeIds`, `chainId`), `vpn:log`, `vpn:readyz` (carries `{ hops: [{ profileId, name, status, body }] }`), `vpn:metrics` (exit hop only; whitelist lives in `preload.js`, keep in sync).

## Chains (nested tunnels)

wireproxy cannot route its own tunnel through an upstream proxy, so chaining is done
at the app level: hop *i>0* runs with a **derived config** (written to
`userData/chain-run/<uuid>.conf`, deleted on stop; orphans swept at startup) where
`[Peer] Endpoint` is rewritten to `127.0.0.1:<relayPort>`, and a `UdpOverSocksRelay`
forwards its WireGuard UDP datagrams through the previous hop's SOCKS5 tunnel
(SOCKS5 UDP ASSOCIATE, RFC 1928). Rules:

- First hop keeps its real endpoint; every later hop's endpoint is rewritten.
- Every non-exit hop gets a deterministic `[Socks5] BindAddress = 127.0.0.1:<freeport>`
  (injected if missing; auth stripped) and loses the non-SOCKS routine sections
  (`[http]`, tunnels) to avoid port clashes. The exit hop keeps its full original
  config (incl. auth/[http]/tunnels) — only the endpoint is rewritten.
- Chain hops must have exactly one `[Peer] Endpoint` (enforced in `chains:save` and
  at startup): extra endpoints would be dialed directly, bypassing the chain.
- Health: `connected` only when **all** hops' `/readyz` are 200; any 503 → `degraded`,
  any unreachable → `connecting`. `/metrics` is polled from the exit hop.
- One dead hop kills the whole run (a partial chain is useless); startup uses a
  `runToken` so a superseded `startRun` never touches a newer run's hops, and
  `stopCurrent`/`startRun` attach `exit` waiters **before** `kill()` (missed-event hang otherwise).

## Autostart / autoconnect / tray

- `autostart` = Windows login item via `app.setLoginItemSettings`. For the **portable** build it MUST pass `path: process.env.PORTABLE_EXECUTABLE_FILE` (runtime exe lives in a temp dir, otherwise the Run key points at the wrong path). `autostartEnabled()` reads back with the same `path` option.
- `autoconnect` reuses the internal `startVpn(id, text, silent)`; it is triggered after the window's `did-finish-load` (so the renderer already subscribes to `vpn:*` events). Target = `defaultTarget` from `settings.json` (`{kind:'profile'|'chain', id}`); legacy `defaultProfileId` is migrated on read.
- Tray keeps the app alive: `window-all-closed` is a no-op and the window's `close` event is intercepted (hide, unless `quitting` set by `before-quit`). Quit only from tray menu. `app.requestSingleInstanceLock()` prevents a second instance (important with autostart) — no duplicate wireproxy spawns.
- Tray menu mirrors the same settings setters used by the UI; `settings.js` is the source of truth for tray+UI state.

## VPN state machine

`stopped → validating → connecting → connected/degraded → (error|stopped)`. Driven by:

- config test (`wireproxy -n -c <conf>`) before every start; failure → `error`
- 1s polling of the health endpoint at `-i 127.0.0.1:<freeport>`:
  - `/readyz` 200 → `connected`, 503 → `degraded`, unreachable → `connecting`
  - `/metrics` → wg stats, rendered in the metrics pane

All entry points (UI, tray menu, autoconnect) go through one `startVpn(id, text, silent)`. When switching from a running connection it uses a `runToken` so a superseded `startRun` never touches a newer run's hops, and attaches `exit` waiters before `kill()` (a kill-then-listen order can miss the event and hang the switch forever).

## wireproxy.exe CLI (all flags that matter)

```
-c <path>        required on Windows (default paths are Unix-only)
-i <host:port>   enables health endpoint (GET /readyz, GET /metrics)
-n               config validation only; prints "Config OK" to stdout
-s               silent mode (suppresses logs)
-d               detaches a background child (do NOT use from this GUI)
-v / --version   prints version to stdout
```

Stdout/stderr: a normal run redirects stdout→stderr internally; `-n` and `-v` print to stdout. Spawn without `-d` and `kill()` the tracked child PID on stop (see `index.js`).

## Config file format

INI-style; full reference in `wireproxy-awg/README.md`. Sections this app deals with:

| Section | Purpose |
| --- | --- |
| `[Interface]` | (Amnezia)WG params incl. obfuscation Jc/Jmin/Jmax/S1-S4/H1-H4/I1-I5 |
| `[Peer]` | peer keys, endpoint, AllowedIPs, PersistentKeepalive |
| `[Socks5]` / `[http]` | SOCKS5 / HTTP(S) proxy (`BindAddress`, optional auth, CertFile/KeyFile) |
| `[TCPClientTunnel]` / `[TCPServerTunnel]` / `[STDIOTunnel]` / `[UDPProxyTunnel]` | tunnels |
| `[Resolve]` | DNS strategy: `ipv4` / `ipv6` / `auto` (default) |

Gotchas: top-level `WGConfig = <path>` imports an existing config; AmneziaWG params go directly in `[Interface]`; values starting with `$` resolve from env (`$$` = literal `$`).
